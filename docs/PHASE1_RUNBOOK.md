# Phase 1 local operation

PostgreSQL 16 is production persistence; the existing `pg` driver is retained.
The application remains native Node.js JavaScript. No TypeScript compiler or bundler is needed.
Node 24 and installed Microsoft Edge are used for acceptance.

## Local database and app (PowerShell)

```powershell
docker compose up -d postgres
$env:DATABASE_URL='postgres://abo_dev:abo_dev_password@127.0.0.1:55432/adaptive_business_os'
npm run migrate
$env:BUSINESS_ID='arktrov'
$env:ENABLE_DEV_TRANSITIONS='1'
npm start
```

Open http://127.0.0.1:3000. DATABASE_URL selects PostgreSQL; without it, JSON is a development fallback.
The displayed business is the local operator context configured by BUSINESS_ID (default ARKTROV).
Request headers/body cannot switch this context. This is a localhost-only internal tool, not a deployed multi-user authentication system.
Transitions are disabled unless ENABLE_DEV_TRANSITIONS=1; POST to a job's transitions endpoint always uses the central state machine.
The UI reads state and references only through the API. QA/publish null values mean no results exist.

## Reproducible acceptance (PowerShell)

```powershell
$env:TEST_DATABASE_URL='postgres://abo_dev:abo_dev_password@127.0.0.1:55432/postgres'
npm run acceptance
npm run lint
npm run build
node scripts/check-foundation.mjs
```

Each run creates a new empty `abo_test_<uuid>` database, applies all migrations, executes all tests, and drops that database.
Both runs therefore include a clean migration and the full app-process restart test. No development schema is truncated.
The user in TEST_DATABASE_URL must be able to create/drop test databases; this is a local test role, not an application deployment role.
A single run is `npm test` with the same variable set. Browser tests launch installed Edge headlessly.
Migration runner records applied filenames transactionally and serializes execution. It adopts the historical manually applied 001 baseline and applies additive 002.
Development passwords in Compose are local placeholders, not production secrets. Real credentials stay in ignored environment files.

## Persisted contract

Job Detail returns job, stateHistory (ordered by database sequence), evidence, artifacts, quality and publish.
The legacy transitions alias remains available.
Evidence exposes evidence_id, business_id, content_job_id, evidence_type, source, reference, payload, content_hash, created_at.
Artifact exposes artifact_id, business_id, content_job_id, logical_name, version, content_hash, storage_reference, source, created_at.
Composite foreign keys reject a job from a different business. UPDATE/DELETE triggers reject mutation of artifact and evidence records.
Omitted artifact version allocates max+1 under a transaction-scoped advisory lock; explicit duplicates fail the database unique constraint.
No binary assets or provider outputs are generated by these tests.
