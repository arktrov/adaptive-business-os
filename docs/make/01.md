## Purpose

Score a selected idea for ARKTROV narrative and business potential without claiming research verification.

## Trigger

Story Pipeline H=Selected for Check, limit 1; module 3 repeats the same guard. No direct consumer of Status=Idea.

## Inputs

Selected story's supplied topic, hook, category, source strength, source URLs, fact summary and notes; no external research.

## Outputs

Scores, evaluation reason, narrative fields and Status=Evaluated on the original row. Original Hook is preserved; Anomaly Hook is a separate field.

## Google Sheets dependencies

Story Pipeline read A1:Z1, write by named headers including narrative fields through AC. Header snapshot at U:Z is blank-labelled; write footprint exceeds read range.

## Google Drive dependencies

None.

## Data structures

Strict arktrov_story_evaluation: viral/business/originality/confidence/suspense scores plus evaluation/narrative fields. Prompt defines 0–10 and allowed conceptual values; exported numeric schema uses integer types without score minimum/maximum.

## Status transitions

Selected for Check → Evaluated unconditionally after model result. No score-threshold, rejected or Research Ready branch.

## APIs / providers

OpenAI Responses configured gpt-5.5; no web tool; store=true. Google Sheets.

## Error handling

No explicit exception route or invalid-business-score gate. Model schema conformance alone does not guarantee prompt score semantics.

## Retries / idempotency

Same row update is repeatable but a model rerun may produce different scores; no lock/in-progress claim or response checkpoint. Concurrent runs can select the same first row.

## Upstream scenarios

00B produces Idea, but selection into Selected for Check is outside the complete set.

## Downstream scenarios

02 requires Research Ready; promotion from Evaluated is outside the complete set.

## Known special cases

Evaluation is not fact approval. Prompt distinguishes a compelling investigation/anomaly from trivia, defines story_driver, open loop, retention driver and story mode, and pairs a specific conversation trigger with a complementary pinned comment. No explicit automated threshold enforces this.

## Business logic to preserve

Truthful hook and ending, supplied-evidence-only evaluation, honest scoring, ARKTROV fit, non-generic retention and discussion logic. Keep original and proposed hook distinct.

## Technical implementation to replace later

Versioned scoring policy, validation and explicit selection decision/event; typed narrative record instead of fragile header/range mappings.

## Required validation

T03: score bounds, missing input, no fabricated facts, all narrative fields and unchanged original hook; wider columns and manual/external promotion.
