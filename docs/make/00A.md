## Purpose

Find evidence-led ARKTROV story ideas and submit discovery as a durable, asynchronous provider request.

## Trigger

First module is a model call; no input watcher or business-row filter. Start is external to the exported flow. Schedule and activation are not exported.

## Inputs

Current date/time plus discovery instructions; no Story Pipeline, prior idea inventory or business profile is read.

## Outputs

OpenAI response ID; DiscoveryJobs record keyed by that ID: agent=discovery, status=pending, attempts=0, created_at, response_id, last_checked_at, empty error_message.

## Google Sheets dependencies

None. The Story Pipeline write occurs only in 00B.

## Google Drive dependencies

None.

## Data structures

Strict arktrov_discovery_v1: discovery_run {run_summary, search_scope, ideas_found, ideas_selected} and ideas[]. Ideas carry title, provisional_hook, story_summary, category, core_emotion, extraordinary_element, viral/failure reasons, visual_direction, audience, source/date URLs, source_strength, eight scores, evergreen potential, priority, recommended_status=Idea, selection_reason and duplicate_search_terms. ideas allows 1–8 entries; duplicate terms 2–6 and additional URLs at most 5.

## Status transitions

Provider submit → DiscoveryJobs.pending. No story is created in this scenario.

## APIs / providers

OpenAI Responses through Make createModelResponse; configured gpt-5.6-terra, required web_search_preview, high search context/reasoning, background=true, store=true, createConversation=true. These are exported settings, not a fresh availability check. Make Data Store persists the request.

## Error handling

No explicit error route. Submission can succeed before the Data Store insert fails, leaving a provider request without a local polling record.

## Retries / idempotency

Data Store AddRecord uses response ID as key with overwrite=true. This prevents duplicate records for the same response, not duplicate discovery submissions. No source/story deduplication or submit reconciliation.

## Upstream scenarios

External scenario start; no upstream Make scenario evidenced.

## Downstream scenarios

00B polls the matching DiscoveryJobs store.

## Known special cases

Discovery input PromptVersion 1.0.0 and director instructions 2.0.0 coexist. Requests internal consideration of ≥20 candidates and 3–8 selected ideas, with quality over quota, while the schema forbids an empty ideas list. 18–28s short framing contrasts with 00B's Longform label and 03/05 durations.

## Business logic to preserve

Evidence before virality; LostWorlds/DarkPlaces/BeyondEarth pillars; current global search (normally last 14 days) or valuable evergreen; truthful first-two-second hook, proof asset, 6–10 visual states, stop/proof/escalation/payoff/echo progression. Primary genuine URLs, independent confirmation where possible, no fabricated mystery or certainty. Prompt thresholds fascination/hook/credibility/brand fit ≥7 and honest 1–10 scores are editorial requirements, not deterministic gates. Retain the exclusion rules, duplicate-search intention and provenance.

## Technical implementation to replace later

Versioned brand/editorial configuration plus a durable discovery job boundary. Replace embedded account/model choices and Make Data Store mechanics only after parity. Proposed only.

## Required validation

T01: zero-quality run versus schema minimum; submit/persist crash; duplicate submit; preservation of editorial exclusions and truthful hooks.
