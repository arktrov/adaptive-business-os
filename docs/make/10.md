## Purpose

Append YouTube channel observations and then an Instagram media insight observation.

## Trigger

First module GETs current authenticated YouTube channel. No exported cadence, activation or publication event.

## Inputs

Two separately configured YouTube/OAuth connections; reports date range now−2 days to now−1 day; configured Instagram account's first returned media (limit 1).

## Outputs

Platform Analytics append for YouTube channel and append for Instagram media, with different time/grain semantics.

## Google Sheets dependencies

Platform Analytics only, positional INSERT_ROWS/USER_ENTERED. No Content Calendar read, publication lookup, checkpoint or Costs write.

## Google Drive dependencies

None.

## Data structures

YouTube channels items[].id/snippet/statistics and Analytics rows with day/views/estimatedMinutesWatched/averageViewDuration/likes; Instagram metrics aggregated as name + values then selected by name.

## Status transitions

None: appends observations without content/workflow transition.

## APIs / providers

YouTube GET /v3/channels?part=snippet,statistics&mine=true; OAuth HTTP GET youtubeanalytics.googleapis.com/v2/reports with channel==MINE and dimensions=day; Instagram for Business GetUserMedia/GetMediaInsights; Sheets. No supplied publishing call.

## Error handling

HTTP stopOnHttpError=true; no error routes. A YouTube failure blocks the later Instagram steps. ifempty(...;0) masks missing YouTube analytics values.

## Retries / idempotency

Append-only snapshots; no unique observation/checkpoint key. Running both 10 and 10B can duplicate IG observations. Same-account authorization for the separate YouTube connections is not established by the blueprint.

## Upstream scenarios

Existing externally published channel/media; no Make publisher evidenced.

## Downstream scenarios

Platform Analytics consumers/learning are outside the complete set.

## Known special cases

YouTube Views uses lifetime channel.viewCount and Followers Gained uses total subscriberCount; watch/likes use only the first daily report row, while Date is now. Mappings use `9.Data` but HTTP interface declares `data` (lowercase): likely invalid reference, runtime effect unverified. Instagram selects first media, not all publications and not explicitly Reels-only; exact duplicate logic in 10B.

## Business logic to preserve

Separate provider metric identities, date/grain, media IDs and collection timestamps; IG views, watch durations, likes/comments/shares/saves/reach/interactions/reposts/skip rate and permalink. Preserve raw observations so definitions can be corrected without erasing history.

## Technical implementation to replace later

Publication-bound checkpoint observations, explicit availability/null and units, normalized channel vs media grain, same-account validation, independent provider jobs and deduplication. Do not reproduce misleading metric labels as target definitions.

## Required validation

T11: Data/data reference, report columns/dates, absent vs zero, subscriber total vs gain, OAuth identity, unsupported media, independent failures and duplicate observations.
