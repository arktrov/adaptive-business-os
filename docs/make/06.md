## Purpose

Copy assets and emit the existing flat Make render manifest for the external Drive-synchronized worker.

## Trigger

Production C=Assets Ready, limit 1; A1:BZ1. No producer for Assets Ready is in the complete set.

## Inputs

Production IDs, S Short 1 script, AE visual-plan JSON string, AF character timing JSON; up to 20 Assets selected by Story ID and nonempty File Link.

## Outputs

Copies of asset files and Render-{ProductionID}.json in queue incoming; Production C=Render Queued, AG=Queued, AY=Render-{ProductionID}.

## Google Sheets dependencies

Production Pipeline read/update A:AZ (0..51 mapped); Asset Library read by B Story ID + G File Link. No QA Status, asset status, production version or format predicate.

## Google Drive dependencies

Read each File Link via get(split(FileLink; "/"); 5), upload bytes under original fileName to D-QUEUE-INCOMING. Upload manifest to the same flat directory after aggregation.

## Data structures

Make handoff schemaVersion string 1.0: jobId, storyId, productionId, format=short, compositionId=ArktrovVideo, shortScript, visualPlanJson string, voiceTiming {characters, character_start_times_seconds, character_end_times_seconds}, assets[] and output {fps=30,width=1080,height=1920,fileName={ProductionID}.mp4}. Assets carry assetId, scene, assetType, fileName, fileLink, status, qaStatus, sourceId, publicUrl, durationMs, aiGenerated boolean and licenseRights.

## Status transitions

Assets Ready → Render Queued, Timeline Compile Status → Queued; no render completion/failure writeback exists in this scenario.

## APIs / providers

Google Sheets, Google Drive, Make JSON parser/creator. No render provider API call: execution is external Remotion worker through local Drive sync.

## Error handling

No explicit error route. Invalid Drive link, missing/timing parse error, truncated assets or partial uploads can leave queue files and an unadvanced row. Manifest-after-assets is not proof that local Drive synchronization finishes in that order.

## Retries / idempotency

No queue claim/single-writer fence in Make. Same Render ID and filenames can be uploaded repeatedly; worker idempotency is a separate contract and does not hash actual asset bytes/renderer revision in the inspected baseline.

## Upstream scenarios

04 voice + 05/05B visuals plus external QA/readiness. Fixed V004 restriction is upstream, not in 06.

## Downstream scenarios

External Make-handoff normalizer/compiler → Project v1 → Remotion → result.json completed/failed. No supplied Make scenario consumes the result or authorizes publication.

## Known special cases

Selection by Story ID alone can mix revisions, longform/short assets and multiple voiceovers, and limit 20 truncates larger sets. Pending asset QA is forwarded, not enforced. This manifest is NOT Production V2; preserve all existing renderer boundaries separately.

## Business logic to preserve

Exact Make handoff field names/types, embedded visual-plan string, character timing precision, source/AI/rights metadata, shot identity and media basename mapping, existing composition/output contract. SUCCEEDED means rendered, never released.

## Technical implementation to replace later

Explicit asset revisions and completeness checks, durable queue submission/result correlation, atomic readiness/claim and storage references; retain the external renderer behind the compatibility adapter.

## Required validation

T10: canonical legacy fixture; missing/extra/duplicate versions; >20 assets; bad Drive link; timing/script mismatch; partial sync; replay; Pending QA must not imply release.
