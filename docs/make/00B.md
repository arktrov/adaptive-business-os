## Purpose

Poll discovery jobs, materialize returned ideas in Story Pipeline, and update polling state.

## Trigger

Data Store search status=pending, limit 10, no continuation on empty result. Poll frequency/activation unknown.

## Inputs

DiscoveryJobs.response_id and attempts; provider status, output/content text and error message.

## Outputs

One Story Pipeline append per selected idea; pending, failed or completed job updates. Story IDs use timestamp plus iterator index.

## Google Sheets dependencies

Story Pipeline: named-header writes for Story ID, Topic, Hook, Category, Notes, Owner, Status, Fact Status/Summary, Target Format, scores, source URLs and evaluation/recommendation. INSERT_ROWS, USER_ENTERED.

## Google Drive dependencies

None.

## Data structures

Dynamic ParseJSON has no configured named structure. Reads discovery_run.ideas_selected and ideas[] from each iterated output content text. Persists a reduced projection of the 00A schema.

## Status transitions

pending + completed response → ideas with Status=Idea and separate job completed route; failed response → failed/attempts=1/error; router fallback → pending, unchanged attempts, updated check time.

## APIs / providers

OpenAI generic GET /v1/responses/{response_id}; Make Data Store and Google Sheets.

## Error handling

Failed provider status has an explicit business branch. No ParseJSON/Sheets exception handler. Output and content are iterated without a text-type guard. Completion bookkeeping is on a separate matching router route, not a transaction with all appends.

## Retries / idempotency

No backoff, timeout or increasing attempts on waiting; cancelled/incomplete/other status reaches pending fallback. Append and completion are not atomic: replay after partial write can duplicate ideas; no lookup by stable idea/source ID.

## Upstream scenarios

00A via the same DiscoveryJobs reference.

## Downstream scenarios

An external/unrepresented transition from Idea to Selected for Check is required before 01.

## Known special cases

Story ID literal is `ARK- {YYYYMMDD-HHmmss}-{iteratorIndex}` with a space after the hyphen. Target Format is fixed YouTube Longform; Owner fixed ARKTROV Discovery. Additional URLs use capital `I` as separator. Rich discovery fields and duplicate terms are not persisted. Empty idea results, multiple output blocks and independent close-route behavior need run evidence.

## Business logic to preserve

Asynchronous response correlation, provenance, selected idea scores and reasons, genuine source links, and separation of pending/failed/completed outcomes.

## Technical implementation to replace later

Durable polling/reconciliation, typed output extraction, idempotent idea materialization and atomic checkpointing. Preserve external IDs at the adapter.

## Required validation

T02: partial append/replay; zero ideas; non-text content; cancelled/incomplete timeout; all router paths; correct close-after-persistence.
