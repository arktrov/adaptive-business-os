# Optional voice and business voice profiles

Voice is a composition requirement, not a global business-OS dependency. New plans persist voice_required and zero, one or more voice_requirements. The approved package may supply voice_configuration with voice_required and named voice slots (text, language, duration, optional profile ID/style/use case/channel/format/content type). Explicit false bypasses both profile and credential checks and does not add a missing VoiceAsset to the manifest. Visual, rights and other audio requirements remain independent. Legacy immutable plans derive their requirement from their stored narration; they are not rewritten. V005 therefore still requires voice.

BusinessVoiceProfiles are business-scoped, provider-independent immutable revisions in business_voice_profiles (migration 008). Candidate creation never approves. Provider/model/exact voice reference, settings, language compatibility, source references, status, version, timestamps and content hash are persisted. Missing historical fields remain null/empty, never inferred. No provider credentials or headers are permitted, including nested fields. Data is outside job artifacts because a business may reuse profiles across jobs.

BusinessVoiceProfiles.candidate creates an inactive revision. decision requires an explicit human actor, decision reference and expected current hash; approval and retirement append revisions without updating the earlier row. Approval requires an exact provider reference and known language support. A reference change creates a new candidate requiring new approval. Retired or superseded approvals cannot be selected. Unique business/profile/version keys, business foreign keys, immutable triggers and advisory transaction locks protect identity and concurrency. No profile mutation endpoint is exposed to untrusted API callers.

Selection filters the latest revision by business, APPROVED status, language, requested style, use case, content type, channel/format restrictions, explicit workflow selection and provider availability. Empty compatibility lists mean unrestricted for that dimension; an explicit requested style must match. More than one match raises VOICE_PROFILE_SELECTION_REQUIRED; none raises VOICE_PROFILE_MISSING. There is no vendor/default fallback. Before admitting a synthesis attempt the normal AssetService rechecks the exact persisted current approved profile under the profile lock. The immutable admission/request captures the selected profile version/hash; later retirement does not rewrite admitted historical attempts. Each voice slot has its own request/attempt/asset mapping. Legacy single-voice calls remain supported.

Future customer flow: choose whether composition needs voice, browse a provider catalogue or authorized custom/import/clone capability, select a provider reference, name the profile, specify compatibility/settings, preview under a separate call authorization, then approve/select or replace/retire. Catalogue discovery, paid preview and custom-voice creation are not implemented or called here. CUSTOM, IMPORTED and CLONED profiles require provider authorization and human consent references before approval. These are consent records, never credential references. Provider adapters must enforce actual provider permission/consent procedures; the domain exposes no cloning shortcut. No vendor SDK/API contract is changed in this task.
