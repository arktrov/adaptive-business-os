# Human voice approval and offline timing

VoiceTimingService records the explicit human listening decision for an existing, independently byte-validated VoiceAsset. It binds business/job, selected creative Script/Package, exact audio and artifact hashes, approved persisted VoiceProfile revision, provider request ID, QA snapshot, source reference/hash, human actor and approval timestamp. No provider interface is used. Existing audio and QA are never overwritten.

One job-locked PostgreSQL transaction appends asset_human_voice_approval, a production_packages timing-only revision, asset_package_timing, and a new manifest. Exact repetition reuses the existing IDs; changed decision identity fails. Database immutability triggers protect approval and package; rollback leaves no partial approval. Reserved asset_* evidence cannot be forged through the generic HTTP evidence endpoint.

The original human-selected creative package remains selected. The new ProductionPackage version is its timing derivative, not a new script or creative approval. Its parent package/hash, VoiceAsset/hash and voice approval/hash identify its authority. Existing planned requirement IDs continue to reference the unchanged creative requirements; no generation is authorized. Job detail exposes timing revision references under assetProduction and the full derivative in productionPackages.

The manifest retains its base package/plan identity and names effective_production_package_id/hash. Every subsequent manifest reloads and deterministically verifies the timing derivative against immutable source records. It cannot silently revert to the old estimate or become ASSETS_READY using old scene durations. Visual mappings are marked RETIME_REVIEW_REQUIRED; future asset work must consume the effective package's timing and validate its adaptation. No renderer integration is implemented here.

Timing uses decoded audio sample counts at the recorded sample rate. Optional measured edge silence becomes non-destructive source-in/source-out metadata with playback_rate 1. Original MP3 bytes are unchanged. Trim metadata is application planning only (METADATA_ONLY_NOT_RENDERED); a future renderer must honor and verify it. Profile duration limits are evaluated against effective runtime. Conflicts remain explicit PLATFORM_DURATION_LIMIT blockers; there is no automatic speed-up or profile relaxation.

Current repository capabilities provide audio decoding, silence/clipping checks and exact source text, but no verified word/segment forced alignment. Therefore approved segment duration weights are allocated proportionally to the effective narration sample frames, then the existing beats are allocated within their corresponding narration segments. Contiguous sample-grid boundaries cover the complete interval without cumulative drift. This is APPROXIMATE_PROPORTIONAL, not measured speech alignment. Exact text, claim links, visual briefs, classifications, rights, disclosure, generation routing, pause and emphasis cues remain intact. Continuous motion already specified by each brief is retained across its new duration; no extra factual visuals or arbitrary static holds are introduced.

Subtitle preparation retains exact script text/hash, approximate segment/source timings and expected future verified local or human alignment. It is UNRESOLVED / APPROXIMATE_NOT_FINAL, never final captions. The current timing path handles one continuous narration; multi-voice alignment fails explicitly rather than guessing.

Voice synthesis resolution remains independent of rights review. Human quality/pronunciation/brand/pacing approval does not clear usage rights. Publication HOLD TRUE; RELEASE_ALLOWED FALSE; no state transition, visuals, renderer or publication in this operation.
